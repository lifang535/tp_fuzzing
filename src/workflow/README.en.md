# Workflow modules

The campaign mixes native Region/probe generation with ExtendedProgram generation. See the [project README](../../README.en.md) for usage and parameters. The numbered steps below focus on the native route.

Generation, mutation and the oracle resolve target policies, emitters, process options and diagnostics through `src.backends.get_backend()`. Target implementations live in `src/backends/tilelang/` and `triton/`; common script assembly lives in `src/backends/common/`, while reference interpreters and execution checks live in `src/workflow/emitter/`. New backends implement `src/backends/base.py` and register through `register_backend()`; `--backend-plugin MODULE` loads registration modules.

1. `ProgramGenerator` samples the extended domain with `extended_prob`, otherwise delegates to `RegionGenerator.generate()`. New CLI campaigns default to 0.25; the library default is 0.
2. `program_template()` constructs every helper and entry skeleton before `instantiate_program()` binds any SSA values. Native programs have 1–3 helpers by default, with calls to earlier definitions, including inside nested regions. Fresh native entries choose load/GEMM with equal probability by default.
3. `instantiate_function()` builds the entry and samples shapes/types/scheduling for the whole program. V4 values track fp16/fp32, tile/row/column/scalar shapes and tensor/buffer kind. Generated helpers still take 1–3 full fp32 tiles and return one full fp32 tile; explicit compact signatures are supported by the IR.
4. `RegionProgram.validate()` checks scope, arity, regions, bounded loops, types and acyclic calls. Triton emits JIT helpers; TileLang emits macros. The reference interpreter executes calls in isolated function scopes.
5. Mutation explicitly switches storage dtype, locally edits operands/leaf operations/attributes, rebuilds structures, or resamples parameters. Local edits preserve scopes and the call graph. Only Region and Extended programs are accepted; probe generation and mutation also return RegionProgram.
6. Recursive emitters produce Triton/TileLang source plus deterministic input creation and an independent reference interpreter. V4 dispatches to `src/backends/common/typed_emitter.py` for mixed shapes and memory operations.
7. The oracle runs each test in a subprocess and checks results, crashes and timeouts. Fresh native reproducers default to 2 input seeds, 3 executions per configuration and legal 128/256-thread pairs, with output guards and input-integrity checks. V4 additionally checks each block's scratch guards. Beyond the thread pair, fresh programs run schedule sweeps (num_stages, loop_kind variants sharing one reference), an alternate layout pair, the tilelang pass-config invariance pair (a deterministic (program, seed)-sampled subset of the numerically-neutral pool, with the int8 pool excluding `tirx.disable_vectorize` and the pool including `tl.disable_warp_specialized` — inert on sm_89, a real warp-specialization differential on TMA machines; triton gets `enable_fp_fusion=True`), a `T.use_swizzle` variant and `GemmWarpPolicy` FullRow/FullCol variants (gemms with all warps along M/N; per-tile math untouched, one shared reference; filtered per-policy by warp-partition feasibility). Execution settings persist in region v3/v4 IR.
8. With a nonempty seed pool the fuzzer selects 50% mutation / 50% fresh generation, and handles deduplication, persistence, seeds, resume and structural feedback. Filenames contain only static call relationships and a full IR hash. summary.json records `root_cause_locations` (`root_cause → location → count`) for fine-grained localization (invariance label / last TILESMITH_STAGE marker / TVM pass name / reporting source file). Feedback includes types, shapes, memory access, function counts, arities and call-chain lengths.

Directed probes remain restricted whole-function templates with specialized checks. Disable them with `--probe-prob 0`. They use RegionProgram throughout generation, mutation, persistence and emission.

Native predicates can use tile rows, columns, checkerboard coordinates or induction indices. `index_add` introduces indices into tile arithmetic. Loops support 0–4 trips, induction starts 0–3 and steps 1–3. Fresh loops reserve a final carry merge within their budget; local mutation can still change dependencies. Helpers receive row, column and induction context; nested loops restore outer induction context on exit.

Native layouts share stride, offset and storage-size calculations in `ir/layout.py`. GEMM independently selects six layouts for A/B; load mutates only A's layout. Non-contiguous inputs use flat physical buffers with explicit addresses, while the reference uses logical tensor views. Integrity checks include the entire physical storage and padding. Broadcast initialization writes only unique addresses.

The MLIRSmith-style op-surface expansion adds new compiler code paths on both IRs: native regions gain transcendental elementwise ops (tanh/erf/log/log2/exp2/rsqrt/sin/cos/floor/ceil) and int8 GEMM-only programs (spec from the pre-validated `INT8_SPEC_GRID`: block_K ∈ {32, 64}, int32 accumulator, exact integer reference). fp32 GEMMs are never combined with boundary step ops (ceil/floor/round/cast), so TF32 rounding-boundary noise cannot drown the oracle. New-op attributes come from per-(op, backend) bounded instance grids in `generator/grids.py`: round-robin cursors make every corner cell appear exactly once per sweep (cursors persist with the campaign rng state; `--no-instance-grids` restores pure random sampling).

`--typed-op-prob` defaults to 0.35; set it to 0 for fresh v3 controls. New memory operations compose inside if/for and helpers: `load_input` rereads inputs, `store_tile` initializes block-private global scratch, `write_tile` updates an aliased buffer, and `load_tile` snapshots it. Nested regions may capture buffers, but handles cannot escape through yields or calls. The reference masks branch side effects and respects zero-trip loops. Scratch is poisoned and guarded for every launch; the generator shrinks M/N to fit the default 64 MiB scratch budget.

Historical single_op/pipeline/dynamic models, emitters and wrappers have been removed; those records are rejected on resume. Native Region v1–v4 and Extended records remain readable. Native GEMM remains an entry operation, and native reductions/transpose include padded lanes. Native generated interfaces retain full fp32 tiles. The extended domain adds explicit SSA matmul, heterogeneous multi-result interfaces, full scratch checking and compiler feedback, plus global-memory atomics (commutative add/max/min), scalar FMA chains, triton shape primitives (flip/interleave/join/split) and int8 x int8 matmul with an int32 accumulator. Each extended program also compiles deterministic-random pass pipelines sampled purely from (program, seed) (`backends/common/knobs.py`; every pool key has a consumer verified in the installed tilelang 0.1.11). Explicit shared-memory allocation and async copies still do not exist as IR constructs; they are reached only through pass knobs. Warp specialization is likewise TMA-gated (sm_90+) and reached through the `tl.disable_warp_specialized` knob; on this sm_89 machine the `GemmWarpPolicy` FullRow/FullCol variant pair covers warp-partition structural variation.
